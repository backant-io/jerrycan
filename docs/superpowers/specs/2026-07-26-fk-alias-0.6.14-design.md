# belongs_to fk alias — two references to the same entity (0.6.14) — #119

**Date:** 2026-07-26
**Status:** Approved design, pre-implementation
**Issues:** #119 (MEDIUM — `belongs_to` hardcodes the fk column as `snake(target)+"_id"` with no alias, so an entity needing two references to the same target — `Transfer{from_account, to_account}`, a threaded `Comment{parent_comment}`, any self-reference — collides on a single `{target}_id` column and can't be expressed. Builders fall back to plain `i64` fields, losing the generated FK, ON DELETE, and scoped accessors. Hit by round-5 apps: ledger, feed.)
**Ships as:** 0.6.14 — an additive contract feature. Byte-identical for every `belongs_to` that declares no `as` (the fk column derivation is unchanged when `as` is absent).

## A. Contract: `belongs_to { entity, as? }`
Add to `BelongsTo` (design.rs:262):
```rust
/// Optional fk-column alias (issue #119): the fk column becomes `{as}_id` instead
/// of `snake(entity)_id`, so two `belongs_to` the same entity (a ledger's
/// from/to account, a self-reference) coexist. `as` is a Rust keyword — the field
/// is `r#as` with `#[serde(rename = "as")]`. Absent ⇒ today's `snake(entity)_id`,
/// byte-identical.
#[serde(default, rename = "as", skip_serializing_if = "Option::is_none")]
pub r#as: Option<String>,
```
Mirror in `docs/contracts/design-schema.json` (pinned by `tests/contracts.rs`) — an optional `as` string (snake_case pattern).

## B. The one derivation point: `BelongsTo::fk_column()`
Add:
```rust
impl BelongsTo {
    /// The fk column this belongs_to derives: `{as}_id` when aliased, else the
    /// default `snake(entity)_id` (issue #119).
    pub fn fk_column(&self) -> String {
        match &self.r#as {
            Some(a) => format!("{a}_id"),
            None => Design::fk_column(&self.entity),
        }
    }
}
```
`Design::fk_column(target: &str)` (design.rs:1067) stays — it derives a column from an ENTITY NAME (tenancy fk, identity fk) and has no alias. **The rule: every fk column derived FROM A `belongs_to` uses `b.fk_column()`; every fk derived from an entity name (`tenancy.entity`, `identity.entity`) keeps `Design::fk_column(&name)`.**

## C. Thread `b.fk_column()` through EVERY belongs_to-fk site (the mechanical core)
Replace `Design::fk_column(&b.entity)` with `b.fk_column()` at all of these (verified call sites — the reviewer must confirm none is missed):
- **Emission:** genroute.rs:984, 1026, 1132, 1182, 2618 (scoped accessors, DTO fk, table DDL); openapi.rs:251, 253; testgen.rs:214, 218 (fixture fk seeds); schema.rs:341.
- **Reverse-lookups / column collection (CRITICAL — a miss here corrupts tenancy/FK resolution):**
  - design.rs:1028 — `child_fk` in a `tenant_path` JOIN chain (the transitive tenancy JOIN SQL).
  - design.rs:1172 — the `AUTH_IDENTITY_FK_COLUMN` (`user_id`) identity check: use `b.fk_column()`. **Intended consequence:** an *aliased* `belongs_to` the identity entity (e.g. `as: "sender"` → `sender_id`) is correctly NOT the owner fk (a plain reference), while an un-aliased `belongs_to User` → `user_id` stays the owner — this is the desired semantics (a message's sender/recipient aren't "the owner").
  - design.rs:1295, genroute.rs:1291, migrate/mod.rs:747 — fk-column-name collections.
  - genroute.rs:1595 — `find(|b| b.fk_column() == path.joins[0].child_fk)` (the flat-grandchild transitive parent lookup).
  - questions.rs:668, 1480 — fk-column sets used by lints/validation (JL0006 owned-handler set; the composite-unique valid-column set from #115 — an alias must count as a valid fk column there).
  - schema.rs:147 — `b.fk_column() == column` (column→belongs_to match).
- **DDL FK constraint:** the `ForeignKey::create().from(table, {fk})` for a belongs_to must use `b.fk_column()` and REFERENCE the target's pk (find the belongs_to FK emission — likely genroute.rs table builder ~2618 — and ensure both the column and the constraint name use the alias, so two FKs to the same table have distinct names).
- **FK constraint NAME:** if constraint names are `fk_{table}_{fk_col}` they auto-disambiguate via the alias; verify two belongs_to to the same entity produce two distinct constraint names.

## D. Validation — `JC0560` (next free after JC0559)
Register **JC0560** (codes.rs + explain + completeness test, mirroring JC0559) and refuse in the per-entity validation loop (questions.rs):
- two `belongs_to` on an entity whose `fk_column()` values COLLIDE (two refs to the same entity without distinct `as`, or an `as` colliding with another belongs_to's derived fk) — the migration would emit a duplicate column; refuse with the "add distinct `as`" fork.
- an `as`-derived fk column (`{as}_id`) that collides with a declared **field** name or the pk `id`.
- (optional, low-cost) a malformed `as` (not `^[a-z][a-z0-9_]*$`).
Message cites `jerrycan explain JC0560`.

## E. testgen / OpenAPI / realtime / migrator
- testgen: fixtures that seed a belongs_to fk already iterate `.belongs_to` (testgen.rs:214-218) — with `b.fk_column()` they seed `{as}_id` correctly. A two-ref entity needs BOTH parents seeded under their alias columns; verify the fixture seeds each.
- OpenAPI: the request/response schema fk property name follows `b.fk_column()` (openapi.rs:251-253).
- realtimegen.rs / storagegen.rs: if they derive a belongs_to fk, thread `b.fk_column()` (grep both for `fk_column(&b.entity)` — none showed in the audit, but confirm they don't derive it another way).
- migrator (migrate/entities.rs, migrate/mod.rs:747): reverse — a discovered fk column `{x}_id` referencing table `T` where `snake(T) != x` must emit `belongs_to { entity: T, as: x }` (round-trip). If out of scope, emit without alias only when `snake(T)_id == column`, and for a mismatch either set `as` or document the gap — do NOT silently drop the reference. Prefer setting `as` (it's a small, correct addition).

## F. Byte-identity + gates
- A `belongs_to` with no `as` derives the same column as today (`BelongsTo::fk_column()` falls through to `Design::fk_column(&entity)`), so every existing design is byte-identical. Prove via `determinism.rs` + base-vs-HEAD scaffold `diff -r`.
- **Heavy eval gate (0.6.11 lesson):** `reference_eval` + `conformance` + `eval` `--include-ignored` before done.
- **Fixture proof:** add a design with (1) a two-ref entity `Transfer { belongs_to Account as from_account, belongs_to Account as to_account }` and (2) a self-reference `Comment { belongs_to Comment as parent }`. Assert: the migration emits `from_account_id` + `to_account_id` (two FKs to `accounts`, distinct constraint names) and `parent_id` referencing `comments`; a scaffolded correct handler passes `jerrycan check`; the un-aliased case is byte-identical. Add as a conformance/unit fixture.
- `cargo semver-checks`: `BelongsTo` gains a serde-default field — additive (same shape as 0.6.1/0.6.5/0.6.8/0.6.13 pub-field additions).

## Success criteria
- `Transfer { belongs_to Account as from_account, belongs_to Account as to_account }` → columns `from_account_id`, `to_account_id`, two distinct FKs to `accounts`; a self-ref `Comment { belongs_to Comment as parent }` → `parent_id` → `comments`.
- Two un-aliased `belongs_to` to the same entity, or an `as` colliding with a field/fk → **JC0560**.
- Every `belongs_to` with no `as` is byte-identical; heavy gate green; semver clean; published 0.6.14.

## Non-goals
- Many-to-many join tables. A `belongs_to` referencing a non-pk column. Aliasing the tenancy/identity fk itself (those derive from the entity name by design). Cascade-path changes from self-references (an FK cycle's ON DELETE is the author's declared `on_delete`).
