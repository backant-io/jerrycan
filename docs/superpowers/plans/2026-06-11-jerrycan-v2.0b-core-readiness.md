# jerrycan v2.0b — Core Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the core substrate the v2 feature phases assume — dual-lane bodies with per-route limits, param-carrying mounts that extract correctly, request-free DI, background-task lifecycle, an injectable Clock — plus the two correctness-class fixes from the frontend→backend eval (JL0004 public-endpoint carve-out; cross-module FK DDL) and the deferred hardening items (MCP line cap, threat model).

**Architecture:** The serve engine moves to a two-phase read (route first, then read the body under the matched route's policy), which is what makes per-route limits and a future streaming lane possible. `Response` switches to a boxed body type now so v2.1's `StreamBody` is a feature, not a core change. DI resolution gains a task context (synthetic, HTTP-extractor-rejecting) rather than a trait ripple. Lifecycle is builder-level (`App::on_serve`), so the `Extension` trait stays frozen. Single-param `Path<T>` binds the **last** (leaf-most) captured param, which fixes mount-prefix shadowing without a naming scheme.

**Tech Stack:** existing core only (hyper 1, http-body-util, tokio); no new dependencies.

**Reference map:** all file:line anchors below refer to the recon of commit `7e5940d` (crates/jerrycan-core/src/): engine `app.rs:164-273`, body buffering `app.rs:195-241` (`BODY_LIMIT` :169), dispatch `app.rs:366-405`, `RequestCtx` `extract.rs:13-19`, `Path` single-param `extract.rs:83-87` (`params.first()`), sealed `PathParam` `extract.rs:54-79`, DI `dep.rs` (`ProviderFn` :17, resolve :83-110, `DepFactory` :142-181), `Extension` `app.rs:45-47`, middleware `middleware.rs`, TestApp `test_client.rs:132-150` (calls `dispatch` directly), `Response = http::Response<Full<Bytes>>` `response.rs:12`, MCP loop `platform/mcp.rs:13-28`.

async fn background_tasks_start_on_serve_and_drain_on_shutdown() {
    use std::sync::{Arc, atomic::{AtomicBool, Ordering}};
    let started = Arc::new(AtomicBool::new(false));
    let stopped = Arc::new(AtomicBool::new(false));
    let (s2, p2) = (started.clone(), stopped.clone());
    let app = crate::App::new().on_serve("probe", move |_deps, mut shutdown| async move {
        s2.store(true, Ordering::SeqCst);
        let _ = shutdown.changed().await;
        p2.store(true, Ordering::SeqCst);
    });
    let listener = tokio::net::TcpListener::bind("127.0.0.1:0").await.unwrap();
    let (tx, rx) = tokio::sync::oneshot::channel::<()>();

    tokio::time::sleep(std::time::Duration::from_millis(50)).await;
    assert!(started.load(Ordering::SeqCst));

    h.await.unwrap().unwrap();
