## Non-goals
#50's remaining halves (dynamic topics, tenant publish) — feature work, not 0.4.1. No docs restructuring beyond the lines above. No new contract surface unless a fix strictly requires it (then STOP and reassess the version bump).

## Method (per standing convention)
One branch/PR per package, TDD, adversarial review before PR, merge only on a verified-green gate. Constraints: embedded_sync twins byte-identical; local `cargo semver-checks` (7-crate gate command) clean BEFORE every commit — any pub-API change = STOP, the patch bump is forfeit; no-drift proof for generator changes (base-vs-branch scaffold `diff -r` of both conformance designs, intended diffs justified); plain commit messages, one `Fixes #N` line per issue.

## Release + publish (after all three PRs merge)
1. Bump every workspace `version = "0.4.0"` → `0.4.1` + lockfile; CHANGELOG entry (fold the unreleased 0.4.0 notes into it); semver-gate comment stays truthful (baseline note).
2. Dispatch `heavy.yml` from main and require GREEN — the heavy suite has not run since PR #26; no publish on an unproven main.
3. Run `scripts/publish.sh` (it orders deps and has the completeness guard). If crates.io auth is missing, stop and report — never work around auth.
4. Verify: `cargo search`/crates.io API shows 0.4.1 for ALL workspace crates incl. storage/realtime/jobs/ratelimit; then a smoke: scaffold an app against the PUBLISHED crates (no JERRYCAN_FRAMEWORK_DEP path override) and `cargo build` it — the eval's standing distribution blocker is dead only when this passes.
5. Tag `v0.4.1`, push tag; update gate comment's published-baseline to 0.4.1 (next break ⇒ 0.5.0).

## Success criteria
All 8 issues closed by merged, review-gated PRs · heavy suite green pre-publish · 0.4.1 live on crates.io for every crate · a path-dep-free scaffold builds · CHANGELOG/tag/baseline comment consistent. Fail loud at any gate: a red gate, semver hit, or auth gap halts the release, never gets worked around.
