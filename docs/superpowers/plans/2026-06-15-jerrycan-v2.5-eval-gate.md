# jerrycan v2.5 — The eval gate (0.2.0 release condition)

> **For agentic workers:** plan + design spec. The deliverable is a *real
> backend* (the Reference slice) built on jerrycan, served live, with every v2
> feature exercised over real HTTP — and that battery wired as a permanent,
> un-skippable release gate. This doubles as the goal's full E2E.

**Goal (spec §v2.5):** an agent can rebuild the Reference slice via MCP docs-only;
pass requires `jerrycan check` green, generated acceptance tests green (incl.
cross-tenant isolation), a **live HTTP battery** (tenant isolation, webhook
signature rejection, multipart CSV import, API-key scopes, both crons firing
under the test clock, OAuth connect against the mock IdP), and answering
data-structure questions from `schema.json` alone. Pass rate + cold-build time
recorded in the README; the eval becomes a permanent gate.

**Strategy:** there are two layers, and we build BOTH:
- **(A) Deterministic battery** — a CI-runnable `#[ignore]`d test that scaffolds
  the Reference slice, applies *reference handler fixtures*, gets check green, serves
  it live (sqlite), and drives every feature over raw HTTP + a cron-under-clock
  check + schema.json assertions. This is the un-skippable gate ("like clippy").
- **(B) Docs-only LLM eval** — a dispatched opus agent rebuilds the slice using
  only `jerrycan docs`/MCP, scored, recorded in `conformance/eval/results.md` +
  README. The "real" eval; semi-automated.

**Substrate (read first — from recon):**
- `conformance/designs/reference-slice.design.json` — the slice (tenancy, JWT+roles,
  db/relations, 2 crons, leads w/ json + `/import` 202, api-keys, billing webhook).
- `crates/jerrycan/tests/eval.rs` — the fixture-apply harness (scaffold →
  copy `conformance/eval/fixtures/<spec>/<module>_handlers.rs` → check → serve →
  raw-HTTP smoke). Match this pattern.
- `crates/jerrycan/tests/conformance.rs:858` `reference_slice_scaffold_passes_check`
  — the existing reference probe (red-on-stubs, cold-build timing). MUST stay green
  after our additive design edits.
- The v2 primitives the fixtures use: `jerrycan-core` `Multipart`/`TestPart`
  (`multipart.rs`, `test_client.rs`), `jerrycan-auth` `webhook::verify_sha256_hex`,
  `ApiKey`/`require_scope`/`ApiKeys`/`InMemoryApiKeyStore` (`api_key.rs`),
  `oauth::{OAuthClient,Provider}` + `mock_idp::MockIdp` (gated `oauth`/`mock-idp`),
  tenancy scoped repos (`get_for`/`all_for`/`remove_for`), jobs `JobsHandle`/
  `Worker`/`cron_tick_once` + `Clock::test`.
- `crates/jerrycan/src/platform/schema.rs` `SchemaContract` — the schema.json shape.
- `README.md:114-150` (roadmap + eval section), `conformance/eval/PROTOCOL.md`,
  `scripts/publish.sh`, `.github/workflows/ci.yml:55-59` (the `--include-ignored`
  heavy-test step).

## Phase 5a — Make Reference the complete v2 showcase + build the reference backend

### Additive design edits (no contract change — modules/fields/routes are contract-v1)
Edit `conformance/designs/reference-slice.design.json`:
1. ApiKey entity: add `{ "name": "scopes", "type": "string" }` (comma-separated
   scope list, stored at rest). Add a scope-gated read endpoint on the api-keys
   module that requires an `ApiKey` credential with a given scope — e.g.
   `{ "operation_id": "usage", "method": "GET", "path": "/usage", "success": {
   "status": 200 } }` (handler enforces `require_scope`).
2. New module `integrations` (OAuth connect): endpoints
   `GET /auth/google/connect` (success 302) and `GET /auth/google/callback`
   (success 200; errors 400 on a bad/expired code). No entities (token storage is
   handler-owned: an encrypted column or in-memory for the slice).
After editing, **re-run** `cargo test -p jerrycan --test conformance
reference_slice_scaffold_passes_check -- --include-ignored --nocapture` and fix any
assumption it makes about the exact module/endpoint set so it stays green.

### Reference handler fixtures
Create `conformance/eval/fixtures/reference/<module>_handlers.rs` for every module,
implementing the real backend with v2 primitives. Also the jobs task fixtures
(`crates/jobs` task stubs) and any shared wiring. Specifically:
- **users**: `register` (argon2 hash, 409 on dup email via JC0409), `login`
  (verify password → issue a JWT via `jerrycan::auth::jwt`/`Auth`). Public routes.
- **workspaces**: list/create/show; create seeds the caller as `owner` member
  (tenancy membership) so subsequent tenant-scoped calls work.
- **leads**: tenant-SCOPED CRUD (`*_for(workspace_id)` repo accessors so JL0006
  passes + the generated isolation test goes green); `create_lead` 409 on dup
  phone; `delete_lead` owner-only (403 else); **`import_leads`** parses a
  `multipart/form-data` CSV via the `Multipart` extractor, inserts each row,
  returns 202 with a count.
- **api-keys**: list/create (mint via `jerrycan::auth::api_key::mint`, store the
  hash + prefix + scopes, return the plaintext ONCE), owner-only revoke, and the
  new scope-gated `usage` endpoint using the `ApiKey` extractor + `require_scope`.
- **billing**: `stripe_webhook` reads the RAW body (`RawBody`) + the signature
  header, `verify_sha256_hex(secret, raw, sig)` → 200, else 400.
- **integrations**: `connect` builds `OAuthClient::new(Provider::google(), …)`
  `authorize_url(state, scopes)` → 302 redirect; `callback` exchanges the code
  (via the injected transport — in the slice, wired to the mock so it's
  hermetic) and stores the encrypted token. The OAuth client + mock are gated
  `#[cfg(feature="...")]` — the generated app's Cargo features must enable
  `jerrycan/oauth` (+ `mock-idp` for the test). Document the feature wiring.
- **jobs**: `expire_trials` + `overdue_callbacks` reference bodies (idempotent,
  trivial real work — e.g. mark trial workspaces expired / log overdue leads).

**Done when:** scaffolding the edited Reference design + applying these fixtures →
`jerrycan check` is GREEN (build+clippy+tests+lints+schema), the generated
acceptance tests (incl. the tenant-isolation test) PASS, on sqlite. Commit the
fixtures + design edit.

## Phase 5b — The live battery test (the gate)

Create `crates/jerrycan/tests/reference_eval.rs`, one `#[ignore]`d test
`reference_slice_live_battery` (heavy: scaffolds/builds/serves). Pattern off
`eval.rs` + the live-server precedents in `conformance.rs`. Steps:
1. Scaffold the Reference design (framework-dep wired), apply the 5a fixtures,
   `jerrycan --json check` → assert `ok`.
2. Run the generated acceptance suite (`cargo test` in the workspace) → assert
   green (this is the cross-tenant isolation guarantee, already generated).
3. Serve live: `JERRYCAN_ADDR=127.0.0.1:0`-style (bind a free port),
   `JERRYCAN_SECRET=<test>`, sqlite db url, `cargo run -p app`; poll until up.
4. **Battery over raw HTTP** (assert each):
   a. register + login → capture JWT/cookie.
   b. create workspace A & B (two users); A creates a lead; **B cannot read A's
      lead** (404 + absent in B's list) — live cross-tenant isolation.
   c. billing webhook: bad signature → 400; correct HMAC-SHA256 sig over the raw
      body → 200.
   d. `POST /leads/import` multipart CSV (2 rows) → 202; the rows appear in A's
      `GET /leads`.
   e. API-key: create a key with scope `leads:read`; calling the scope-gated
      endpoint with it → 200; a key lacking the scope → 403.
   f. OAuth: `GET /auth/google/connect` → 302 with a `state`; drive the callback
      against the mock IdP → token stored (200).
5. **Crons under the test clock** (in-process, not the live server — deterministic
   via `Clock::test`): build the app `into_test()`, advance the clock past each
   cron's schedule, run `cron_tick_once`/the cron leader, assert BOTH
   `expire_trials` and `overdue_callbacks` enqueue+run. (A live server uses real
   time; the clock-driven check is the spec's "under the test clock".)
6. **schema.json Q&A**: load the scaffold's `schema.json`, assert the
   `SchemaContract` answers the structural questions the eval poses — leads has a
   FK `workspace_id → workspaces.id ON DELETE cascade`, `phone` is unique+indexed,
   `status` is an enum `{new,called,dnc}`, api-keys FK to workspaces, etc. (This
   proves schema.json alone is sufficient to answer data-structure questions.)
7. Record cold-build time (reuse the conformance timing) into the test output.

Wire it into CI (`.github/workflows/ci.yml` `--include-ignored` step) and into
`scripts/publish.sh` as a pre-publish gate (alongside conformance/eval). Keep it
sqlite-based so CI needs no DB service.

## Phase 5d — Run the docs-only LLM eval

Dispatch an opus subagent under the extended PROTOCOL: rebuild the Reference slice
docs-only (CLI + `jerrycan docs`/`explain` only; NO framework source, NO
fixtures), loop check to green, verify a live round-trip, and answer 3-5
schema.json data-structure questions using only `jerrycan schema`. Score it,
write the result into `results.md` + README. Honestly record gaps/bugs it
surfaces and FIX any real framework bugs found (that's the eval's purpose).

## Phase 5e — Full-estate + real-infra verification (the 95%-confidence sweep)

Beyond CI-green: stand up **Dockerized Postgres + Redis** and:
- Run the jobs Postgres ignored tests (`cargo test -p jerrycan-jobs --test
  postgres_store -- --ignored`, `JERRYCAN_TEST_PG_URL=…`) and the Redis ignored
  tests (`--features jobs-redis … redis_store -- --ignored`).
- Serve the Reference app against **real Postgres** (not just sqlite) and re-run the
  HTTP battery — proves the SeaORM Postgres dialect, `FOR UPDATE SKIP LOCKED`
  leasing, and the `pg_advisory_xact_lock` cron leader for real.
- Run the auth `oauth` real-socket test, the multipart fuzz, the cron fuzz smoke.
- Final sweep: `cargo fmt --check`, `clippy --workspace -D warnings`, workspace
  tests, facade all-features tests, `RUSTDOCFLAGS=-D warnings cargo doc`,
  `--no-default-features` build, `cargo audit`/`deny`, `embedded_sync`,
  conformance/eval/genroute_compile `--include-ignored`.
- Report confidence with the concrete evidence (what ran, against what infra,
  what passed). Fix any gap found.
