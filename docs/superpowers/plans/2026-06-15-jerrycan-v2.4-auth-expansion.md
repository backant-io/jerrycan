# jerrycan v2.4 — Auth expansion (jerrycan-auth)

> **For agentic workers:** this is the plan + design spec. TDD, plain commits.
> Auth is the highest-stakes surface — a final dedicated security review gates
> the phase. All new code is `#![forbid(unsafe_code)]` (already on the crate).
> Hand-roll envelopes over **vetted RustCrypto/rustls primitives only** (the
> crate's existing philosophy: see `jwt.rs`/`session.rs` module docs).

**Goal:** finish the auth surface Kolli needs — OAuth2 authorization-code client
with refresh (provider presets), encrypted-at-rest token storage with key
rotation + zeroize, scoped API keys, and a mock IdP test harness — without
breaking any existing `jerrycan-auth` API or the design contract.

**Substrate (read before starting):**
- `crates/jerrycan-auth/src/lib.rs` — `Auth` extension, `derive_key(secret,label)`
  labeled KDF, `from_env`/`with_secret`, `MIN_SECRET_LEN`.
- `crates/jerrycan-auth/src/session.rs` — `SessionStore` (ChaCha20-Poly1305 AEAD,
  `base64url(nonce‖ct+tag)`). Token-at-rest reuses this codec.
- `crates/jerrycan-auth/src/guard.rs` — `FromRequest` extractor pattern
  (`ctx.resolve::<Auth>()`, `Headers`, 401/403). `ApiKey` follows this.
- `crates/jerrycan-auth/src/webhook.rs` — constant-time compare via `hmac`'s
  `verify_slice`; the hex_encode/hex_decode helpers (reuse for API-key hashing).
- `crates/jerrycan-auth/src/jwt.rs` — HS256 envelope (style reference).

**Dependency justifications (supply-chain policy):**
- `zeroize` — already transitively in the tree (via rustls). Direct dep so key
  material (`Zeroizing<[u8;32]>`, master secret bytes) is wiped on drop.
- `hyper-rustls` + `http-body-util` + `bytes` (behind the new `oauth` feature
  only) — OAuth2 code-exchange/refresh need an outbound HTTPS client.
  `hyper`/`hyper-util` are already workspace deps; `hyper-rustls` reuses the
  already-present `tokio-rustls`/`webpki-roots` (rustls-only, no openssl). This
  is a far smaller footprint than `reqwest`. The base crate (no `oauth`) gains
  nothing.

## Task 1 — Key rotation, zeroize, encrypted token-at-rest

**Files:** `crates/jerrycan-auth/Cargo.toml` (add `zeroize`), `src/session.rs`,
`src/lib.rs`. **Tests:** in those modules.

The rotation story (spec §v2.4): rotating `JERRYCAN_SECRET` must NOT invalidate
existing sessions/tokens. Achieve it with **multi-key decrypt**: encrypt with the
current (primary) key; decrypt by trying the primary then each retired key.

- `SessionStore`: hold a primary `ChaCha20Poly1305` plus `Vec<ChaCha20Poly1305>`
  fallbacks.
  - Keep `SessionStore::new(&[u8;32])` working (single key, no fallbacks) — it is
    called from existing code/tests.
  - Add `SessionStore::with_keys(primary: &[u8;32], fallbacks: &[[u8;32]])`.
  - `encode` uses the primary only. `decode` tries primary, then each fallback in
    order; returns the first success, else `JC0401` (unchanged error surface).
  - Wrap raw key bytes in `zeroize::Zeroizing` where they live as `[u8;32]`
    locals; the `ChaCha20Poly1305` cipher owns its key internally (don't fight
    its API — just zeroize the transient `[u8;32]` derivations).
- `derive_key` returns `Zeroizing<[u8;32]>` (or callers wrap it) so intermediate
  key bytes are wiped. Keep the function signature ergonomic; `Zeroizing<[u8;32]>`
  derefs to `[u8;32]`.
- `Auth`:
  - Add `with_secrets(primary: &str, retired: &[&str]) -> Self` deriving primary
    + fallback session keys and the token-cipher key for each.
  - `from_env`: read `JERRYCAN_SECRET` (primary) and optional
    `JERRYCAN_SECRET_OLD` (comma-separated retired secrets). Each retired secret
    must also meet `MIN_SECRET_LEN` in prod (skip empties). Existing single-secret
    behavior unchanged when `JERRYCAN_SECRET_OLD` is unset.
  - Add a **token-at-rest codec** for OAuth tokens: a `SessionStore`-typed field
    keyed with a distinct label (`derive_key(secret, "oauth-token")`), multi-key
    like sessions. Expose `Auth::tokens(&self) -> &SessionStore`. (Generated apps
    encrypt an OAuth `TokenResponse` with `auth.tokens().encode(&t)?` before
    persisting the ciphertext in a DB column, and `decode` on read — rotation
    applies automatically.)

**Tests (intent — encode WHY):**
1. A token encrypted under the OLD primary still `decode`s after the secret is
   rotated to a new primary with the old one listed as retired — proves rotation
   doesn't log everyone out.
2. A token encrypted under a secret that is NOT in {primary, retired} fails 401 —
   retiring a key for real eventually invalidates it.
3. `tokens()` and `sessions()` ciphertexts are NOT cross-decryptable (label
   separation) — a leaked session key can't read tokens-at-rest and vice-versa.
4. `from_env` with `JERRYCAN_SECRET_OLD="a,b"` builds two fallbacks; prod rejects
   a short retired secret.

## Task 2 — Scoped API keys

**Files:** `crates/jerrycan-auth/src/api_key.rs` (new), `src/lib.rs` (exports).

Mint high-entropy keys, store only their hash, authenticate + scope-check.

- `mint(prefix: &str) -> MintedApiKey` — generates 32 random bytes (OsRng),
  formats the plaintext as `{prefix}_{base64url_nopad(random)}`. Returns
  `MintedApiKey { plaintext: String /* show once */, prefix: String, hash: String
  /* hex sha256 of the plaintext */ }`. The plaintext is never stored.
- `hash_key(plaintext: &str) -> String` — hex SHA-256 (high-entropy keys don't
  need argon2; SHA-256 gives a fast, constant-length lookup column). Reuse the
  `webhook` hex helpers (make them `pub(crate)` if needed, or duplicate the tiny
  encoder).
- `verify(plaintext, stored_hash) -> bool` — constant-time compare of the hashes
  (compare hex via `hmac`-style fixed-time eq, or compare the raw 32-byte digests
  with a constant-time check; do NOT use `==` on the hex `String`).
- `ApiKeyRecord { id, prefix, hash, scopes: Vec<String> }` and a scope check:
  `ApiKeyRecord::require_scope(&self, needed: &str) -> Result<()>` — 403 unless
  `scopes` contains `needed` or the wildcard `"*"`. Free fn
  `require_scope(scopes: &[String], needed: &str) -> Result<()>` too (mirrors
  `require_role`).
- `ApiKeyStore` trait (object-safe, hand-boxed future like `JobStore`):
  `fn lookup<'a>(&'a self, hash: &'a str) -> ApiKeyFuture<'a, Option<ApiKeyRecord>>`.
  Plus `InMemoryApiKeyStore` (a `Mutex<HashMap<hash, ApiKeyRecord>>` with an
  `insert(record)` helper) for tests / the mock + small deploys. Apps back it
  with a DB table.
- `ApiKey(pub ApiKeyRecord)` `FromRequest` extractor: read the key from
  `Authorization: Bearer <key>` OR `X-API-Key: <key>` (Bearer first), `hash_key`
  it, `ctx.resolve::<Arc<dyn ApiKeyStore>>()` (document that the app provides the
  store), `lookup`; `Some(record)` → `ApiKey(record)`, else 401. (Provide the
  store via `app.provide::<Arc<dyn ApiKeyStore>>(...)`; confirm the DI layer
  accepts a trait-object Arc — if not, wrap in a concrete newtype `ApiKeys(Arc<dyn
  ApiKeyStore>)` and resolve that.)

**Tests:**
1. `mint` → `verify(plaintext, minted.hash)` true; a tampered plaintext false;
   the stored `hash` never contains the plaintext tail.
2. Full extractor path through an `App`: a request with a valid `X-API-Key`
   resolves `ApiKey(record)`; missing/garbage key → 401; valid key lacking the
   required scope → 403 via `require_scope`; `"*"` scope passes any check.
3. `verify` is constant-time (at least: doesn't short-circuit on the hex string —
   assert via code shape / a comment; a timing test is out of scope).

## Task 3 — OAuth2 authorization-code client (+ provider presets)

**Files:** `crates/jerrycan-auth/Cargo.toml` (`oauth` feature + deps),
`crates/jerrycan-auth/src/oauth.rs` (new), `src/lib.rs` (gated exports).
Everything in this task is gated `#[cfg(feature = "oauth")]`.

- `Provider` presets — a struct `{ auth_url, token_url, default_scopes:
  &'static [&'static str] }` with constructors `Provider::google()`,
  `github()`, `hubspot()`, `salesforce()` (correct production endpoints; scopes
  as sensible defaults, overridable). Providers are **config, not code** — no
  per-provider branching in the exchange logic.
- `OAuthClient { provider, client_id, client_secret(Zeroizing or secret-wrapper),
  redirect_uri, http: Arc<dyn TokenTransport> }`.
  - `new(provider, client_id, client_secret, redirect_uri)` — default transport =
    `HttpTransport` (real hyper-rustls).
  - `with_transport(self, Arc<dyn TokenTransport>)` — inject the mock (Task 4).
  - `authorize_url(&self, state: &str, scopes: &[&str]) -> String` — pure; builds
    `auth_url?response_type=code&client_id=…&redirect_uri=…&scope=…&state=…`
    (url-encode every param). No network.
  - `authorize_url_pkce(&self, state) -> (String, PkceVerifier)` — S256 PKCE:
    generate a verifier, send `code_challenge`+`code_challenge_method=S256`,
    return the verifier to pass back into `exchange_code`.
  - `async exchange_code(&self, code: &str, pkce: Option<&PkceVerifier>) ->
    Result<TokenResponse>` — POST `application/x-www-form-urlencoded`
    `grant_type=authorization_code&code=…&redirect_uri=…&client_id=…&client_secret=…
    [&code_verifier=…]` to `token_url`; parse JSON.
  - `async refresh(&self, refresh_token: &str) -> Result<TokenResponse>` —
    `grant_type=refresh_token&refresh_token=…&client_id=…&client_secret=…`.
- `TokenResponse { access_token: String, token_type: String, refresh_token:
  Option<String>, expires_in: Option<u64>, scope: Option<String> }` —
  `Serialize`+`Deserialize` (so apps encrypt it via `auth.tokens()`). An OAuth
  error response (`{"error":"…"}`) maps to a clear `Error` (NOT a 500; surface
  the provider error reason without leaking the client_secret).
- `TokenTransport` trait (object-safe, hand-boxed future): `fn post_form<'a>(&'a
  self, url: &'a str, form: &'a [(&'a str, &'a str)]) -> TokenFuture<'a>` →
  `Result<TokenResponse>` (or a raw JSON `Value` the client parses — pick one and
  be consistent). `HttpTransport` is the production impl over hyper +
  hyper-rustls (https) / plain hyper (http, for the localhost mock): build the
  request, send, collect the body (`http_body_util::BodyExt`), parse JSON, map
  transport errors to `Error::internal` (no secret leakage). Use the
  already-present rustls roots (`webpki-roots`).

**Tests (hermetic — use the Task 4 mock transport, no sockets):**
1. `authorize_url` contains the provider's `auth_url`, the encoded `redirect_uri`,
   `response_type=code`, `state`, and the joined `scope`; a `state` with special
   chars is correctly percent-encoded.
2. PKCE: `authorize_url_pkce` includes `code_challenge` + `S256`; the returned
   verifier S256-hashes to that challenge.
3. `exchange_code` against the mock transport returns the expected
   `TokenResponse`; `refresh` returns a new access token.
4. An `{"error":"invalid_grant"}` response surfaces a non-500 error mentioning
   the reason, and the rendered error never contains the client_secret.

## Task 4 — Mock IdP test harness

**Files:** `crates/jerrycan-auth/src/mock_idp.rs` (new, gated `#[cfg(feature =
"oauth")]`), `src/lib.rs`. **Used by:** OAuth unit tests, generated tests, the
v2.5 live battery.

A deterministic in-process authorization-code + refresh IdP.

- `MockIdp` holds in-memory maps (issued `code → (access, refresh)`, valid refresh
  tokens). Deterministic token minting (e.g. monotonic counter, NOT randomness —
  reproducible tests). `new()` + a way to pre-issue a code:
  `issue_code(&self, code: &str)` returns the access/refresh it will mint.
- `token_transport(&self) -> Arc<dyn TokenTransport>` — an in-process transport
  that answers `post_form` for `grant_type=authorization_code` (validates the
  code, returns its tokens, rotates the code to one-time-use) and
  `grant_type=refresh_token` (validates the refresh token, mints a fresh access
  token). Bad code / bad refresh → an OAuth `{"error":…}`-equivalent `Error`.
  This is what `OAuthClient::with_transport` consumes for hermetic tests.
- `into_app(self) -> App` (or `router`) — mount the SAME logic as real jerrycan
  endpoints: `GET /authorize` (issues a code, 302-redirects to `redirect_uri?
  code=…&state=…`) and `POST /token` (the form exchange). This is the live HTTP
  server the v2.5 battery drives over real localhost HTTP (exercising the real
  `HttpTransport`). Keep the two paths sharing one core so they can't diverge.

**Tests:**
1. `OAuthClient::with_transport(mock.token_transport())` →
   `exchange_code("c1")` returns the tokens `issue_code("c1")` promised; the code
   is one-time (second exchange fails).
2. `refresh` with a token from the exchange returns a new access token; a bogus
   refresh token errors.
3. The mounted `into_app()` server: `into_test()` a GET `/authorize?...` →
   302 with a `code` param; POST `/token` with that code → 200 + JSON tokens.
