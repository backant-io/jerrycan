# jerrycan v2.0 — Data Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land design contract v1 (relations, constraints, enums, json, tenancy, jobs shape), adopt SeaORM 1.x as the generated data layer, and ship the jerrycan-owned `schema.json` DB contract — the one breaking change of v2, done first.

**Architecture:** The design schema gains the full v2 surface in a single `contract_version` bump (jobs engine arrives in v2.3; only the shape lands here). jerrycan-db wraps `sea_orm::DatabaseConnection` (which runs on our existing sqlx stack); generated `model.rs` becomes SeaORM entities, `repo.rs` stays the agent-owned seam. Cross-module `belongs_to` emits FK columns + DDL only (no inter-crate SeaORM `Relation` — route crates stay decoupled). Tenancy generates a membership entity + `Tenant` guard dep in `shared/`, tenant-scoped repo methods, and cross-tenant isolation tests. `schema.json` is derived by applying migrations to a throwaway `sqlite::memory:` and introspecting via PRAGMA — never by parsing SQL.

**Tech Stack:** sea-orm 1.x (`runtime-tokio-rustls`, `sqlx-sqlite`, `sqlx-postgres`, `macros`), existing sea-query 0.32 (platform DDL), serde, sqlite PRAGMA introspection.

**Sequencing note:** This is plan 1 of 7. Plans for v2.0b–v2.5 are written when their phase starts, against the landed reality of this one.

## Locked contract shapes (referenced by every task)

```rust
// design.rs additions — these ARE contract v1; do not improvise field names.
pub struct BelongsTo {
    pub entity: String,                 // PascalCase target entity
    #[serde(default)]
    pub on_delete: OnDelete,            // default Restrict (safest)
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Default, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum OnDelete { Cascade, SetNull, #[default] Restrict }

pub struct Tenancy {
    pub entity: String,                 // e.g. "Workspace"
    #[serde(default)]
    pub member_roles: Vec<String>,      // e.g. ["owner", "member"]
}

pub struct JobDesign {                  // SHAPE ONLY in v2.0 (engine = v2.3)
    pub name: String,                   // ^[a-z][a-z0-9_]*$
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub schedule: Option<String>,       // 5-field cron, validated
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub queue: Option<String>,
}
```

Derivation rules:
- `belongs_to: [{ "entity": "Workspace", "on_delete": "cascade" }]` on entity
  `Lead` ⇒ FK column `workspace_id` (type = target pk type), `NOT NULL`
  unless `on_delete: set_null` (then nullable). DDL FK with the policy.
- `tenancy.entity` must name a declared entity; every entity with a
  `belongs_to` pointing at it is "tenant-owned" and gets scoped repo methods
  + isolation tests.
- Field flags: `"unique": true` (per-column), `"index": true`. String enums:
  `"values": ["a", "b"]` ⇒ DDL `CHECK (col IN (...))`, model stays `String`.
