# jerrycan v2.3 — jerrycan-jobs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Ship the v2 spec's job engine (`docs/superpowers/specs/2026-06-11-jerrycan-v2-design.md` §v2.3): a new `jerrycan-jobs` crate with a `JobStore` trait (enqueue / lease / ack / retry / dead-letter), a **Postgres `SELECT … FOR UPDATE SKIP LOCKED` default store**, a **Redis Streams store behind a `jobs-redis` feature**, in-process workers with **per-queue concurrency**, **cron with skip-missed semantics and a Postgres-advisory-lock leader**, **N retries with exponential backoff → dead-letter**, **idempotency keys**, and **`run_at` delayed jobs** — plus generator emission of typed task stubs + failing acceptance tests from the design's `jobs` objects. Capped semantics (the contract); explicitly NOT built: priorities, workflows/chains, rate-limited queues, delayed fan-out.

**Architecture:** The engine is a new optional crate `jerrycan-jobs` registered as an `Extension` (mirrors `jerrycan-ratelimit`). A `JobStore` trait (object-safe, hand-boxed `Send` futures, **every time-sensitive method takes `now: SystemTime`** so it is clock-free) has three impls: `InMemoryStore` (the `TestApp`/conformance default — pure given `now`, fully deterministic under the injected `Clock`), `PostgresStore` (the production default, always compiled, raw `SKIP LOCKED` SQL via `Db::conn()`), and `RedisStore` (behind `jobs-redis`, Streams + consumer groups + `XAUTOCLAIM`). The worker is a **pure `tick(now)` method** (lease a batch → run each typed task fn under a per-job timeout → ack / retry-with-backoff / dead-letter) that the `on_serve` loop calls on a real-tokio interval and tests call directly (since `into_test` drops `on_serve` tasks). Cron is a separate `on_serve` poller that holds `pg_advisory_xact_lock` while it checks-due → enqueues → advances `last_fired` atomically; the leader is Postgres-only (single-process/in-memory deploys are the trivial leader). At-least-once + lease-expiry reclaim is the correctness mechanism (task handlers MUST be idempotent — generated stubs warn this).

**Tech Stack:** Rust (MSRV 1.88), the existing `Clock`/`Extension`/`on_serve`/`TaskContext` substrate, `jerrycan-db` (`Db`/`Migration`/`backend()`/raw `sea_orm` SQL), `redis` 1.x (+ the `streams` feature, behind `jobs-redis`), a hand-rolled 5-field cron parser (no new dep), `serde_json` for payloads.

**Branch:** `v2.3-jobs` off `main`.

**Decisions taken (reversible pre-publish — flag in final report):**
- Crate name **`jerrycan-jobs`** (not among the 7 reserved crates.io names — like `jerrycan-ratelimit`, needs a 0.0.0 reservation before 0.2.0 publish, which is deferred; renameable until then).
- **Cron is Postgres-advisory-lock leader ONLY** (faithful to the spec's "Postgres-advisory-lock leader"). The Redis store provides queues / delay / idempotency; **Redis-only cron is out of scope for v2.3** (documented). A single-process / in-memory deploy is the trivial leader (no-op lock).
- **`schedule` and `queue` are NOT mutually exclusive** (kolli-slice's `expire_trials` has both): `schedule.is_some()` ⇒ the job is **cron-triggered** (the leader enqueues an instance each due tick); `queue` (default `"default"`) ⇒ which worker pool runs it. Cron jobs take **no payload**; queue-only jobs (no `schedule`) take a **typed `{Name}Payload`** the enqueuer supplies.
- The **Redis Streams store ships now** (spec lists it as v2.3), validated by inspection + an `#[ignore]`d real-Redis test (the `Clock` can't drive Redis server time — determinism lives in the Postgres/in-memory paths).

**Explicitly NOT in this phase (scope fence):**
- **Zero design-contract changes.** `JobDesign{name,schedule,queue}` is frozen at contract v1; `run_at`/idempotency/retries/backoff/max_attempts are **runtime enqueue/extension config**, NOT design fields. `contract_version` stays 1; `design.rs`/`design-schema.json` untouched (a new `questions.rs` validation rule is allowed — it's not the frozen schema).
- No priorities, workflows/chains, rate-limited queues, delayed fan-out.
- No new corpus design — kolli-slice's 2 jobs are the eval fixture.
- No graceful ack-on-shutdown of long jobs — at-least-once + lease reclaim is the mechanism (a job killed at the drain cap re-runs after its lease expires).

#[cfg(test)]
mod tests {
    use super::*;
    use std::time::{Duration, SystemTime};

    fn t0() -> SystemTime { SystemTime::UNIX_EPOCH + Duration::from_secs(1_000_000) }
    fn spec(name: &str) -> NewJob { NewJob::new(name, "default") }

    #[tokio::test]
    async fn at_least_once_a_crashed_lease_is_reclaimed() {
        // lease, DON'T ack (simulate a crash), advance past the lease, re-lease.
        let s = InMemoryStore::new();
        s.enqueue(spec("a"), t0()).await.unwrap();
        let lease = Duration::from_secs(30);
        let leased = s.lease("default", t0(), lease, 10).await.unwrap();
        assert_eq!(leased.len(), 1, "the due job is leased");
        // before the lease expires it is NOT re-leasable
        assert!(s.lease("default", t0() + Duration::from_secs(5), lease, 10).await.unwrap().is_empty());
        // after the lease expires (crash) it IS re-leasable — at-least-once
        let again = s.lease("default", t0() + lease + Duration::from_secs(1), lease, 10).await.unwrap();
        assert_eq!(again.len(), 1, "an expired lease is reclaimed");
        assert_eq!(again[0].attempts, 2, "the reclaim counts as a second attempt");
    }

    #[tokio::test]
    async fn retry_with_backoff_is_not_releasable_until_the_window_elapses() {
        let s = InMemoryStore::new();
        s.enqueue(spec("a"), t0()).await.unwrap();
        let job = s.lease("default", t0(), Duration::from_secs(30), 10).await.unwrap().pop().unwrap();
        let backoff_until = t0() + Duration::from_secs(60);
        s.retry(job.id, backoff_until).await.unwrap();
        // not due until backoff elapses
        assert!(s.lease("default", t0() + Duration::from_secs(30), Duration::from_secs(30), 10).await.unwrap().is_empty());
        // due after
        assert_eq!(s.lease("default", backoff_until + Duration::from_secs(1), Duration::from_secs(30), 10).await.unwrap().len(), 1);
    }

    #[tokio::test]
    async fn dead_letter_holds_the_job_and_it_is_requeueable() {
        let s = InMemoryStore::new();
        s.enqueue(spec("a"), t0()).await.unwrap();
        let job = s.lease("default", t0(), Duration::from_secs(30), 10).await.unwrap().pop().unwrap();
        s.dead_letter(job.id).await.unwrap();
        // not re-leasable while dead
        assert!(s.lease("default", t0() + Duration::from_secs(3600), Duration::from_secs(30), 10).await.unwrap().is_empty());
        // inspectable + requeueable
        let dead = s.list_dead("default", 10).await.unwrap();
        assert_eq!(dead.len(), 1);
        s.requeue_dead(job.id).await.unwrap();
        assert_eq!(s.lease("default", t0() + Duration::from_secs(3601), Duration::from_secs(30), 10).await.unwrap().len(), 1);
    }

    async fn idempotency_key_makes_a_duplicate_enqueue_a_no_op() {
        let s = InMemoryStore::new();
        let first = s.enqueue(spec("a").idempotency_key("k1"), t0()).await.unwrap();
        let second = s.enqueue(spec("a").idempotency_key("k1"), t0()).await.unwrap();

use jerrycan_core::Result;
use std::future::Future;
use std::pin::Pin;
use std::time::{Duration, SystemTime};

/// Boxed Send future the object-safe trait returns (the RateLimitStore pattern).
pub type JobFuture<'a, T> = Pin<Box<dyn Future<Output = Result<T>> + Send + 'a>>;

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum JobStatus { Pending, Leased, Done, Dead }

/// A persisted job row (the TABLE shape — NOT the frozen design `jobs` object).
#[derive(Clone, Debug)]
pub struct Job {
    pub id: i64,
    pub name: String,
    pub queue: String,
    pub payload: serde_json::Value,
    pub run_at: SystemTime,
    pub attempts: u32,
    pub max_attempts: u32,
    pub status: JobStatus,
    pub idempotency_key: Option<String>,
    pub lease_expires_at: Option<SystemTime>,
    pub created_at: SystemTime,
}

/// An enqueue request. `run_at`/`idempotency_key`/`max_attempts` are RUNTIME
/// params (not design fields). Builder style.
#[derive(Clone, Debug)]
pub struct NewJob {
    pub name: String,
    pub queue: String,
    pub payload: serde_json::Value,
    pub run_at: Option<SystemTime>,        // None => now (due immediately)
    pub idempotency_key: Option<String>,
    pub max_attempts: Option<u32>,         // None => engine default
}
impl NewJob {
    pub fn new(name: &str, queue: &str) -> Self { /* payload null, others None */ }
    pub fn payload(mut self, v: serde_json::Value) -> Self { self.payload = v; self }
    pub fn run_at(mut self, at: SystemTime) -> Self { self.run_at = Some(at); self }
    pub fn idempotency_key(mut self, k: &str) -> Self { self.idempotency_key = Some(k.into()); self }
    pub fn max_attempts(mut self, n: u32) -> Self { self.max_attempts = Some(n); self }
}

/// The outcome of an enqueue — a duplicate idempotency key is a NO-OP, not an error.
#[derive(Clone, Copy, Debug)]
pub enum EnqueueOutcome { Inserted(i64), Duplicate(i64) }

/// At-least-once job store (spec §v2.3). Object-safe; every time-sensitive method
/// takes `now` so the store is clock-free and the worker/tests supply the time.
pub trait JobStore: Send + Sync + 'static {
    fn enqueue<'a>(&'a self, job: NewJob, now: SystemTime) -> JobFuture<'a, EnqueueOutcome>;
    /// Atomically claim up to `max` due jobs on `queue`: status=Pending AND
    /// run_at<=now, OR status=Leased AND lease_expires_at<now (a crashed lease).
    /// Sets status=Leased, lease_expires_at=now+lease, attempts+=1. The
    /// SKIP-LOCKED seam in Postgres; a Mutex section in-memory.
    fn lease<'a>(&'a self, queue: &'a str, now: SystemTime, lease: Duration, max: u32) -> JobFuture<'a, Vec<Job>>;
    fn ack<'a>(&'a self, id: i64) -> JobFuture<'a, ()>;                                  // status=Done
    fn retry<'a>(&'a self, id: i64, backoff_until: SystemTime) -> JobFuture<'a, ()>;     // status=Pending, run_at=backoff_until, lease cleared
    fn dead_letter<'a>(&'a self, id: i64) -> JobFuture<'a, ()>;                          // status=Dead
    fn list_dead<'a>(&'a self, queue: &'a str, limit: u32) -> JobFuture<'a, Vec<Job>>;
    fn requeue_dead<'a>(&'a self, id: i64) -> JobFuture<'a, ()>;                         // status=Pending, run_at=now-ish, attempts reset? keep attempts, reset status
}
```
`InMemoryStore`: `Mutex<HashMap<i64, Job>>` + `AtomicI64` id counter + a `HashMap<String, i64>` for idempotency keys. `lease` sorts by `run_at`/`created_at` for determinism, applies the due predicate, mutates under the lock (no await held across the lock), returns clones. `requeue_dead` sets status=Pending + run_at=now (caller's responsibility on time; it's only used by the dead-letter admin path — take `now`? keep it simple: requeue makes it immediately due by setting run_at to UNIX_EPOCH or a passed now — to stay clock-free, have `requeue_dead` set run_at to `SystemTime::UNIX_EPOCH` so it's due; document). Engine default `max_attempts` lives on the worker/extension, but the STORE records the per-job `max_attempts` from `NewJob` (or a default the enqueue caller resolves before calling — pass it resolved). Keep the store dumb: it stores `max_attempts` as given; the worker decides retry-vs-dead-letter by comparing `attempts` to the job's `max_attempts`.

use std::time::{Duration, SystemTime};

#[derive(Debug, Clone)]
pub struct CronSchedule { /* per-field allowed-value sets: minute(0-59), hour(0-23), dom(1-31), month(1-12), dow(0-6) */ }

impl CronSchedule {
    pub fn parse(expr: &str) -> Result<Self, CronError> { /* 5 fields; each parsed to a bitset/Vec of allowed values; reject out-of-range, step 0, bad chars */ }
    /// The first scheduled instant strictly AFTER `after` (UTC, second-aligned).
    pub fn next_after(&self, after: SystemTime) -> SystemTime { /* civil-time decompose `after`→(y,mo,d,h,mi); advance minute-by-minute (bounded, ≤ ~1 year) to the next minute matching all fields; recompose to SystemTime. dom/dow: standard cron OR-semantics when both restricted. */ }
}

#[derive(Debug)]
pub struct CronError(pub String);

/// The single tick to fire now, with skip-missed semantics: the next scheduled
/// instant after `last_fired` (or after a sentinel epoch on first run); if it is
/// `<= now`, return it ONCE (the caller advances `last_fired` to it). Intermediate
/// missed ticks are skipped — a backlog after downtime fires at most once.
pub fn due_fire(schedule: &CronSchedule, last_fired: Option<SystemTime>, now: SystemTime) -> Option<SystemTime> {
    let from = last_fired.unwrap_or(SystemTime::UNIX_EPOCH);
    let next = schedule.next_after(from);
    if next <= now { Some(next) } else { None }
    // NOTE skip-missed: the caller persists last_fired = next, so the NEXT due_fire
    // computes next_after(next); even if several ticks were missed, each call fires one
    // and advances, but the leader only enqueues if it hasn't already (last_fired check),
    // so a long backlog collapses to one enqueue per real tick the leader observes.
}
```
The implementer must do the civil-time math without `chrono` — decompose `SystemTime` → UTC (y,mo,d,h,mi) via days-since-epoch arithmetic (a known algorithm), iterate minutes to the next match (cap the search at e.g. 366 days → error if no match, guarding malformed schedules), recompose. **Exhaustive unit tests are the safety net** — add tests for `,` lists, `-` ranges, day-of-month vs day-of-week, month rollover, leap years.

```rust
impl Worker {
    /// One poll-batch: lease up to `batch` due jobs on `queue`, run each typed
    /// task fn under `exec_timeout`, then ack (Ok) / retry-with-backoff (Err,
    /// attempts<max) / dead-letter (Err, attempts>=max). Returns jobs processed.
    /// PURE w.r.t. `now` — the on_serve loop passes clock.now(); tests pass a
    /// hand-advanced instant. Idempotent task handlers required (at-least-once).
    pub async fn tick(&self, queue: &str, now: SystemTime) -> Result<usize> {
        let jobs = self.store.lease(queue, now, self.cfg.lease_duration, self.cfg.batch).await?;
        let n = jobs.len();
        for job in jobs {
            let Some(task) = self.dispatch.get(&job.name) else {
                // unknown job name (design/handler drift): dead-letter, don't spin
                self.store.dead_letter(job.id).await?;
                continue;
            };
            let ctx = (self.task_context)();   // fresh per job
            let fut = task(ctx, job.payload.clone());
            let result = tokio::time::timeout(self.cfg.exec_timeout, fut).await;
            match result {
                Ok(Ok(())) => self.store.ack(job.id).await?,
                Ok(Err(_e)) | Err(_ /*timeout*/) => {
                    if job.attempts >= job.max_attempts {
                        self.store.dead_letter(job.id).await?;   // exhausted
                    } else {
                        let backoff = backoff_for(job.attempts, self.cfg.backoff_base, self.cfg.backoff_cap);
                        self.store.retry(job.id, now + backoff).await?;
                    }
                }
            }
        }
        Ok(n)
    }
}

/// Exponential backoff: base * 2^(attempts-1), capped. attempts is 1-based
/// (lease incremented it), so the 1st failure waits ~base.
fn backoff_for(attempts: u32, base: Duration, cap: Duration) -> Duration {
    let shift = attempts.saturating_sub(1).min(20);
    base.saturating_mul(1u32 << shift).min(cap)
}
```
