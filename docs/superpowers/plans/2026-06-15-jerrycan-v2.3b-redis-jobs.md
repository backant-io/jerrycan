# jerrycan v2.3b — Redis Streams job store

> **For agentic workers:** this is both the plan and the design spec. Implement
> TDD, plain commits. Reuse the existing `InMemoryStore` contract tests as the
> deterministic CI coverage; the Redis-specific tests are `#[ignore]`d live
> tests (need a local redis), exactly like `jerrycan-jobs`' Postgres tests and
> `jerrycan-ratelimit`'s `RedisStore`.

**Goal:** a durable, multi-node `JobStore` over Redis, behind a `jobs-redis`
feature, that satisfies the *existing* `JobStore` trait (no trait change, no
generator change, no design-contract change) using Redis Streams + consumer
groups + `XAUTOCLAIM` for crashed-worker reclaim — the v2.3 deferral item.

**Architecture:** the trait is `i64`-keyed and the worker holds an id across
`lease → ack/retry/dead_letter`; Redis Streams use string entry ids. Bridge it
with a per-job hash carrying the app `i64` id and its current `stream_id`, an
`INCR` sequence for ids, a per-queue **ready Stream** (consumer group `jc`), a
per-queue **scheduled ZSET** for `run_at`/backoff delays (Streams have no native
delay), and a per-queue **dead ZSET**. Multi-key mutations are atomic Lua
scripts (the BullMQ pattern). Crashed-worker reclaim is `XAUTOCLAIM` over the
pending-entries list (PEL), keyed on Redis-server idle time = the lease.

**Tech stack:** the existing `redis` workspace dep (rustls, no openssl),
`ConnectionManager`, `redis::Script`. No new dependencies.

## Key schema (all keys prefixed `jc:jobs:`)

| Key | Type | Role |
|---|---|---|
| `jc:jobs:seq` | string (INCR) | source of the `i64` job id |
| `jc:jobs:job:{id}` | hash | the full job record (fields below) |
| `jc:jobs:q:{queue}:s` | stream | the **ready** queue; consumer group `jc`; each entry has one field `id={i64}` |
| `jc:jobs:q:{queue}:z` | zset | **scheduled**: member `{id}`, score `run_at` epoch-ms — delayed + backoff jobs |
| `jc:jobs:q:{queue}:dead` | zset | **dead-letter**: member `{id}`, score dead-at epoch-ms (deterministic order) |
| `jc:jobs:idem:{key}` | string | idempotency key → id, set `NX`, **permanent** (no TTL — matches InMemory/Postgres) |

Job hash fields: `name`, `queue`, `payload` (json text), `run_at` (epoch-ms),
`attempts`, `max_attempts`, `status` (`pending`/`leased`/`done`/`dead`),
`idem` (idempotency key or empty), `created_at` (epoch-ms), `stream_id` (the
current Stream entry id while ready/leased, empty otherwise).

`SystemTime` ↔ epoch-ms helpers already exist as a pattern in
`postgres_store.rs` (BIGINT epoch-ms); mirror them.

## Operations (each an atomic Lua script unless noted)

- **`enqueue(job, now)`** — Lua: if `idem` set and `idem:{key}` exists, return
  `Duplicate(existing_id)`. Else `INCR seq` → id; `HSET` the hash; if
  `run_at <= now` `XADD q:{queue}:s * id {id}` and store `stream_id`; else
  `ZADD q:{queue}:z {run_at} {id}` (status `pending`, no stream_id). If `idem`
  set, `SET idem:{key} {id}` (already-checked, so unconditional inside the
  script). Return `Inserted(id)`.

- **`lease(queue, now, lease, max)`** — three sources, capped at `max` total:
  1. **promote** due scheduled jobs: `ZRANGEBYSCORE q:z -inf {now} LIMIT 0 max`;
     for each, `XADD q:s * id {id}`, set `stream_id`, `ZREM` from `q:z`.
     (Lua, atomic.)
  2. **reclaim** crashed workers: `XAUTOCLAIM q:s jc {consumer} {lease_ms} 0
     COUNT {remaining}` — min-idle = the lease, so a still-running job (PEL idle
     < lease) is never stolen; a crashed worker's entry (idle ≥ lease) is
     reassigned. Idle time is Redis-server time, **not** `now` — this is the one
     place the store uses wall-clock instead of the injected clock, inherent to
     Streams; document it.
  3. **new** entries: `XREADGROUP GROUP jc {consumer} COUNT {remaining}
     STREAMS q:s >`.
  For every entry leased (any source): `HINCRBY attempts 1`, set status
  `leased`, build the `Job`. Skip+`XACK`+`XDEL` any entry whose hash is gone
  (acked-then-trimmed races). Return `Vec<Job>` ordered by id.

- **`ack(id)`** — `XACK` + `XDEL` the entry, `DEL` the job hash (terminal; the
  hash is no longer needed). Idempotency key row is left in place (permanent
  dedup).

- **`retry(id, backoff_until)`** — `XACK` + `XDEL` the current entry (clears the
  PEL so it is not reclaimed), `ZADD q:z {backoff_until_ms} {id}`, status
  `pending`, clear `stream_id`.

- **`dead_letter(id)`** — `XACK` + `XDEL`, `ZADD q:dead {now_ms} {id}`, status
  `dead`. (`now` is available; if a caller lacks it, use the hash's `run_at` as
  a stable fallback — but the trait gives us the id only; score with a
  monotonic `INCR`-free value: use the job's `attempts`-bumped `run_at`. Keep it
  simple: score with the current Redis `TIME` is non-deterministic, so score
  with the job id itself — order by insertion — set score = id.) **Decision:**
  score the dead zset by **id** so `list_dead` order is deterministic and stable
  without a clock.

- **`list_dead(queue, limit)`** — `ZRANGE q:dead 0 {limit-1}` (by score=id ⇒ by
  insertion), load each hash → `Vec<Job>`.

- **`requeue_dead(id)`** — `ZREM q:dead`, reset attempts to 0, status `pending`,
  `run_at = now`-equivalent: the trait gives no `now`, so `XADD` straight onto
  the ready stream (immediately leasable) and set `stream_id`. Matches the
  InMemory/Postgres "due immediately, attempts reset" semantics.

Consumer group `jc` is created lazily with `XGROUP CREATE q:s jc $ MKSTREAM`,
ignoring `BUSYGROUP`. Consumer name: a single fixed `jc` consumer is fine — the
PEL tracks per-entry idle independent of consumer, and `XAUTOCLAIM` reassigns by
idle time.

### Task 4: ignored live integration tests

**File:** `crates/jerrycan-jobs/tests/redis_store.rs`, `#[ignore]`d, gated on
`feature = "jobs-redis"`, header documenting
`cargo test -p jerrycan-jobs --features jobs-redis --test redis_store -- --ignored`.
Each test uses a unique queue/key prefix (e.g. derived from the test name) so
runs don't collide on a shared redis. Cover:
1. enqueue → lease → ack roundtrip (status transitions, payload preserved).
2. idempotency: second enqueue with same key returns `Duplicate(id)`, no second
   lease.
3. `run_at` delay: a future job is not leased at `now`, is leased at `run_at`.
4. retry backoff: after a `retry(id, now+Δ)`, not leased before `now+Δ`, leased
   after.
5. crashed-worker reclaim: lease (no ack), wait > a tiny lease, lease again →
   same job re-leased with `attempts == 2` (real time; use a small lease).
6. dead_letter → `list_dead` (deterministic order) → `requeue_dead` → leasable.
