# Face-off round 5: 20 heavy jerrycan apps on published v0.5.0 — bug-hunt (2026-07-20)

Twenty NEW hard backends, one per domain, all jerrycan, cold-start Sonnet
builders, no path-dep override (published **v0.5.0** from crates.io). Each app was
paired with an Opus auditor that verified every builder claim against framework
source at file:line AND mined the builder's `outputs.log` for struggle and
token-burn. **40 agents, 0 errors, 8.28M tokens.** Primary deliverable = the
bug/friction report; the apps are the instrument, not the product.

Domains (20): livestream, fileshare, crm, chat, helpdesk, commerce, auction, feed,
booking, pm, vod, iot, lms, jobs, ledger, health, events, cms, collab, gateway.

**Green ≠ secure.** All 20 reached `jerrycan check` green with a clean build — and
several shipped check-green-yet-insecure defaults: secrets serialize by default
(new #1), a realtime `changes` on the tenancy root broadcasts every tenant's rows
to every principal (new #2), and the transitive-tenancy leak (#102) still passes
`check` on the published release. The headline is that "check ok:true" continues to
under-report the security posture of the generated app.

## What v0.5.0 got RIGHT (fresh-agent re-confirmed)
- **Membership-verified tenancy holds for the ONE-hop shape** — many-membership
  reads/writes, 404-read/403-write, and out-of-set create rejection worked cold
  across the tenancy apps whose graphs stay one level deep.
- **The scoped `*_for_memberships` / `*_for` accessors are correct-by-construction**
  where the generator actually emits them; builders that used them got isolation
  for free.
- Storage, realtime, rate-limit, and cron all function at runtime. The defects
  this round are around those seams (contract-surface, mount-blindness, broadcast
  scoping), not in their runtime cores.

## NEW findings (round 5)

Filed as fresh issues (numbers assigned at filing; see the issue tracker). Ranked
by severity.

1. **(CRITICAL) Realtime `changes` on the tenancy entity itself broadcasts every
   row to every authenticated principal.** When the entity carrying `changes` *is*
   the tenancy root (not a `belongs_to` child of it), `changes_spec` leaves
   `tenant_column: None`; `change_visible(None, _) => true` then fans every insert
   out to every authenticated principal including non-members, with **no scaffold
   warning**. `realtimegen.rs:51`. App: **collab**.
2. **(HIGH) Secrets serialize by default — no `write_only`/response-hidden field.**
   The generated `Model` derives `Serialize` over every column (`genroute.rs`
   ~806), there is no response DTO, and `Field` has no `write_only`/`sensitive`
   flag. The docs' own accounts-api example ships `password_hash` in responses.
   Apps: **jobs, health, gateway, feed, lms**.
3. **(HIGH) Handler stub comments steer to methods the generator never emits.**
   Stub guidance points at `create_for_memberships`/`update_for_memberships` that
   `repo.rs` does not emit for a transitively-owned grandchild under an entity-less
   subroute → following the framework's own generated guidance is a
   method-not-found compile error. `genroute.rs:1132`. App: **livestream**.
4. **(HIGH) Anonymous client cannot reach a scope-"none" realtime topic once an
   auth model exists.** `WsStart::from_request` runs the auth resolver with `?`
   BEFORE any per-topic scope check (`ws.rs:67`), so an anon connect to a public
   topic 401s at the upgrade — directly contradicting `scope_allows(None,None) =>
   Ok`. App: **auction**.
5. **(HIGH) Entity named after a prelude identifier is uncompilable with no
   validate-time guard.** An entity called e.g. `Module` triggers an E0659 cascade;
   nothing rejects it at design-validate time. `genroute.rs:2289`. App: **lms**.
6. **(HIGH, test-infra regression) Shared `CARGO_TARGET_DIR` + identical scaffold
   crate names cross-contaminate concurrent builds.** A stale/foreign
   `libroute_users` linked into a *different* app produced phantom `no such column`
   / 404s costing ~10–12 debug turns. Introduced by the
   `perf/conformance-shared-target` work. Fix: per-app target subdir or
   app-prefixed crate names. Apps: **ledger, lms**. *(This is test-infra, not
   shipped-framework — see Caveats.)*
7. **(MEDIUM) No composite/multi-column UNIQUE.** `Field.unique` is per-field only,
   so "one row per (a,b)" dedup is forced into a racy SELECT-then-INSERT. Apps:
   **feed, jobs, events, lms**.
8. **(MEDIUM) `belongs_to` cannot model two references to the same entity.**
   `fk_column` is hardcoded `snake(target)+_id` with no alias, so
   `Transfer{from_account, to_account}` and self-refs collide → forced into plain
   `i64` fields, losing the generated FK and scoped accessors. Add
   `belongs_to{entity, as}`. Apps: **ledger, feed**.
9. **(MEDIUM) Scaffold is not `cargo fmt --check` clean.** `main.rs` ships
   non-alphabetical `mod` lines and there is no shipped `.rustfmt.toml`; running
   `cargo fmt` reorders them → JL0003 generated-file-drift trips `check` on a file
   no agent touched. App: **helpdesk**.
10. **(MEDIUM) SQLite runtime never issues `PRAGMA foreign_keys=ON`** while the
    scaffold emits `"enforced": true` for every FK → declared FKs and ON DELETE
    CASCADE are silently unenforced on the default backend, contradicting
    `schema.json`. `jerrycan-db/src/lib.rs:46`. App: **events**.
11. **(MEDIUM) `design.json request_body` cannot express a non-entity scalar/DTO
    body** → forces `probe:skip` + a hand-written DTO invisible to
    openapi/schema, and spawns bogus credential/401 TODO wording in no-auth apps.
    App: **commerce**.
12. **(MINOR BATCH — one issue)**
    - (a) **Hollow-green:** `jerrycan check` reports ok with ZERO acceptance tests
      before gen-tests runs (jobs, iot, events).
    - (b) **`probe:"skip"` collateral:** skipping a probe also deletes that
      endpoint's passing `<op>_without_auth_is_401` guard test (jobs, vod).
    - (c) **Identity-entity docs mislead:** docs say the identity entity is
      "typically a User/Account", but only a literal `user_id` fk triggers
      owner-scoping (`design.rs:944`) (auction, feed).

## Struggle / token-burn analysis (top sinks, with framework cause)

1. **Mount-blindness (#81/#82) forced full re-scaffolds.** The literal-mount-param
   / body-trim pair is the biggest single sink: **CRM did two 55-file scaffolds;
   livestream re-scaffolded 3×.** When the generated tests 400 by construction, the
   builder's instinct is to re-scaffold rather than suspect the generator.
2. **SYSTEMIC cold-start doc over-read.** Builders spent **~80% of their output
   reading `jerrycan docs` before writing any design.** There is no scoped doc
   bundle keyed to a `dependencies` set, so every cold agent linearly re-reads the
   full doc surface. This is the largest structural token cost across all 20 apps
   and is not specific to any one domain.
3. **Shared-target-dir contamination produced PHANTOM cross-app bugs** (see NEW #6)
   costing **~10–12 debug turns** on ledger and lms — the builders chased
   nonexistent schema/column bugs that were actually a foreign `libroute_users`
   linked in from a concurrent app.
4. **Hand-rolling transitive tenancy on 0.5.0** (health, cms, lms) — builders wrote
   their own chain-walking guards because the published release lacks them. This is
   an artifact of pinning published 0.5.0; the core is fixed on
   `fix/transitive-tenancy-102`.
5. **JL0006 rename-churn (pm shipped RED).** The naive substring lint (#103) reacts
   to renames, so pm burned turns renaming to appease it and ultimately shipped red.

**Cross-cutting:** the JC0542/JC0544 path-param conflict fired at the very first
`jerrycan new` for roughly **6/10** apps — a first-contact friction that greets
cold builders before they write a line of handler code.

## Caveats (honest accounting)

- **Discount the shared-target phantom bugs (NEW #6).** They are test-infra
  contamination from `perf/conformance-shared-target`, NOT shipped-framework
  defects. They cost real debug turns and are worth fixing in the harness, but they
  do not reflect what a real user of published 0.5.0 would hit.
- **The `health` app's auditor over-escalated a FABRICATED PHI leak**, citing a log
  line that does not exist in the source. That claim is **excluded** — it is the
  one wrong claim this round and is not counted among the findings.
- **Transitive-tenancy hand-roll burn (sink #4) is not a new bug** — it is the
  expected cost of pinning a release whose fix already lives on-branch. Not filed.
- Cross-tenant WRITE relocation via a path-scoped `update_for` was observed but is
  **being fixed by the maintainer on-branch** and is deliberately not filed.

## Verdict

Twenty cold builders reached green on published 0.5.0, and the ownership-safety
core held wherever the graph stays one hop deep — but "green" continued to
over-promise: **check-green-yet-insecure defaults** (serialized secrets, a
broadcast that ignores tenancy, and the still-open transitive leak #102) are the
throughline of round 5. The sharpest NEW find is the CRITICAL realtime-on-tenancy-
root broadcast (collab): a member-less principal receives every tenant's rows with
no warning. The biggest *cost* find is structural, not a bug — mount-blindness
(#81/#82) driving 55-file re-scaffolds, and cold-start doc over-read burning ~80%
of builder output for want of a scoped doc bundle. Fixing those two would move the
token curve more than any single generator patch.
