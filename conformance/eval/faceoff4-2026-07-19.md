# Face-off round 4: 10 heavy jerrycan apps on published v0.5.0 — bug-hunt (2026-07-19)

Ten NEW heavy backends (each stressing multiple hard surfaces), all jerrycan,
cold-start Sonnet builders, no path-dep override (published v0.5.0 from crates.io).
Primary deliverable = the bug/friction report. Two Fable auditors verified every
claim against framework source, file:line. Purpose: find bugs we missed and where
agents struggle, to improve framework guidance.

## What v0.5.0 got RIGHT (fresh-agent confirmed)
- **Many-membership tenancy works** (J2 TeamWorkspace: user in A+B sees both, non-member 404, admin-only enforced).
- **The Supabase membership-set migration is genuinely lossless for the CORE path** (J5): flat routes, `all_for_memberships`/`create_for_memberships`, 404-read / 403-write all worked COLD, 32/32 green, isolation test passed unmodified. **The T2/T6 ownership-safety work HELD** — the defects found are around the core, not in it.
- Storage, realtime, rate-limit, cron all function at runtime.

## What we MISSED — new confirmed findings (ranked)
1. **CRITICAL #102 — transitive tenant leak.** Tenant grandchildren (Contact→Account→Org) bypass EVERY tenancy defense: the `endpoint_tenant_shape`/`tenant_owned` predicate is direct-belongs_to-only and never walks the chain (design.rs:766-768, lints.rs:154). No guard, no scoped methods, no lint, no isolation test → a member of Org A reads Org B's contacts via `GET /orgs/999/accounts/5/contacts`, `check` says ok:true. Residual #78 on deep graphs (the COMMON shape). Corroborated by J6 (Message under Channel under Workspace). **0.5.1 hotfix candidate.**
2. **#103 — JL0006 is a naive substring scan** (false-pos on unrelated `x_repo.get()`, false-neg on renamed/custom-repo leaks, silent skip on nested modules). A weakness in a security lint the whole effort leans on.
3. **#104 — realtime + many-membership is unbuildable** (tenant-partitioned broadcast impossible; WS binds arbitrary first-membership tenant; zero-membership user 403'd off /realtime).
4. **#105 — Supabase migration drops the workspace_members write surface** (no endpoint, no GapKind) and pins jwt-login so it can't return a token.
5. **#106 — no add/remove-member surface** for many-membership tenancy (every tenancy app hand-seeded via raw SQL).
6. **#107 — no atomic reserve-if-capacity**; oversell-safety relies on SQLite's undocumented pool=1 → same code OVERSELLS on Postgres.
7. **#108 — storage non-member → misleading 401** (Option<Dep<Tenant>> swallows the guard's 403/404).
8. **#109 — no dynamic `now()` default** for datetime (server-timestamp fields forced into lossy required:false).
9. **#110 — no public-read/owner-write ownership shape** (J1 auctions, J10 feed — mainstream, unexpressible).

## Where agents STRUGGLE (recurring friction, re-confirming open issues)
- **Generated tests can't test the hard features**: jobs harness never migrates the tables jobs touch (#84, 4 sightings); realtime TestApp can't open sockets / wires no topics (#84, J1+J6 — J6 hand-wrote a WS probe binary).
- **`unique` on a tenant entity is permanently un-greenable AND the docs' `index` fix doesn't work** (#85, re-scoped by J2's verification).
- **Rate-limit is design-invisible → wiring it permanently reddens `check`** (#83, J7, before/after proof).
- **Contract-surface gaps**: field-length (#80, ~every app), dynamic defaults (#109), mount-blind nesting (#81/#82, J9's reds).

## Verdict
The ownership-safety CORE shipped in 0.5.0 is sound under fresh agents — but it was
built and reviewed for ONE-hop tenant children, and the eval's deeper graphs exposed
that multi-hop tenancy, the realtime+tenancy seam, and the "add a member" lifecycle
were never in scope. #102 is the sharpest: a real cross-org leak in a release that
headlines ownership-safety. The recurring friction (#83/#84/#85) is now sighted across
2-3 rounds — those are the highest-confidence guidance fixes.
