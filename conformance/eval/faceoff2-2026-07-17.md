## Headline conclusions

1. **Swap-invariance HOLDS for FastAPI** (85.0K vs 85.8K, same friction/footgun
   classes): the lane profile is a framework+agent property, not an app
   property. Round 1's comparison was NOT app-biased.
2. **The token multiplier is real and persistent**: 2.46× this round (2.21×
   round 1). The R7 docs split's saving was consumed by this round's new bugs —
   the multiplier's floor is set by friction, not by docs weight alone.
3. **Fix efficacy — the round-1 fixes held**: enum→422 HELD (auto-validated),
   entity seeding HELD for clean creates, RealtimeHandle::publish HELD
   (LiveAuction realtime first-class, no self-dial), field defaults HELD,
   per-site auth headers HELD. Cron NOT EXERCISED (TestApp wires no extensions
   → agents steered to the admin fallback; #66). Quality shifted accordingly:
   round 2's jerrycan lane had fewer wrong claims (1 refuted-docs claim vs 4)
   and its one partial was purely a testgen artifact, not a product failure.
4. **New bug surface is one layer deeper**: round 1's traps were contract-level
   (tenancy, jwt, request bodies); round 2's are integration-level — the
   router's param-name conflict (hit by 4/5 builds — #65), TestApp extension
   wiring (#66), role-aware credentials (#67), probe-skip-blind seeding (#68),
   tool-owned-file clobbering (#69).
5. **FastAPI's counter-profile is stable**: 0 framework bugs, 0 wrong claims,
   but 8 security footguns in the same classes as round 1's 7 (never-expiring
   tokens, weak hashing, secrets in source, token leaked to server.log via URL
   query, unauth mutation endpoints). Green tests keep hiding production debt.

## Verdict evolution

jerrycan buys contract-enforced correctness (0 footguns across 10 builds over
two rounds) at a stable ~2.2–2.5× token premium; FastAPI stays cheap, fast, and
silently unsafe. The premium's composition CHANGED between rounds: round 1's
was dominated by contract traps (now fixed), round 2's by integration traps
(#65–#69). Fixing the round-2 batch — especially #65 (4/5 hit rate) and #66
(unlocks cron+realtime in generated tests) — is the next material lever on the
multiplier.
